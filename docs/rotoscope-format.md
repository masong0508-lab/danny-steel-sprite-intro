# ROT2 — fast compact native GBA film format

## Cartridge budget
The verified ROT1 build occupied approximately 3.07 MiB in total (opening cache 1,093,756 bytes), but averaged 21.203 page flips/s rather than the earlier 29.864 FPS. ROT2 trades a small amount of compression for faster aligned word writes. The local sanitizer-backed C decoder test on all 638 samples extracted from the verified raw-cache ROM produced a 1,212,208-byte clip, including directory and padding; all original sampled pixels and guards matched. The 1,258,291-byte per-clip limit remains enforced. Twenty-one clips at the limit plus approximately 2 MiB game consume around 27.2 MiB of the 32 MiB ROM space, leaving approximately 4.8 MiB for growth and distinct scene assets. These are budgets, not guarantees for arbitrary duration/complexity.

## Format and quality
The unchanged 60-Hz logical timeline selects every second exact native 240x135 palette-index picture, including the true final sample. No spatial resampling or color reduction. Little-endian u32 header: ROT2 magic 0x32544f52, sample count, last authored tick, recovery interval (32 samples), total bytes. Then count+1 u32 byte offsets. Each record starts with u16 decoded packet size and u16 LZ4 block size (zero means raw), with 4-byte padding. Each packet consists of u32 headers (low 16 absolute word offset, high 16 positive word count), then that many u32 pixel words. Merge short unchanged gaps to reduce span headers. Recovery packets patch a fixed scene base; others patch the previous exact sample. All writes, record lengths and source bounds are checked. Word runs copy from aligned input to aligned output; LZ4 literals/matches use batched copies. The build checks every raster, guards, and persistent top-matte presentation. The generator is the source of truth; no reference video or owner-private matte files are added.

## Reusable canvas lease
One shared 32 KiB decompression packet serves any film. The normal opening uses the existing game canvas directly, eliminating the separate 38,400-byte picture workspace and picture-to-canvas DMA. The game grants a lease only when the opening dialogue and its fixed matte preserve the picture area, and revokes it before every other draw and new game/exit. The decoder refuses unleased or different canvases. Other movie scenes must explicitly prove that their overlays preserve the leased region before using the same mechanism. Random jumps and backwards seeks seed from the authored renderer or a recovery packet, not a long delta chain. Host galleries and uncached builds retain the live painter. Install host gcc and liblz4-dev; make clean && make OPENING_CACHE=0 selects the original painter. Actual emulator cadence and linked RAM budgets remain release gates.
