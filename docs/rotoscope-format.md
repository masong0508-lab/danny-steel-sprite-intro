# ROT3 — compact native GBA film with independent cue recovery

## Verified baseline and target
ROT2 measured 29.366 presented page flips/s over the opening benchmark (295 flips/600 native video frames); the entire 24-second capture had no dropped input or emulator errors. It retains the 1.2 MiB scene budget. ROT3 removes periodic base resets from sequential playback and adds a small independent recovery table specifically for the authored dialogue cue jumps. A local ASan/UBSan run linked the production ROT3 decoder against the prior verified ROM's 638 samples: 1,232,024 bytes, 9,731 exact presentations, 31 cue/nearby recoveries without live painting. The new linked ROM and mGBA capture are separate release gates; no speed gain is claimed before those measurements. Twenty-one clips at the 1,258,291-byte per-clip cap plus approximately 2 MiB for the game leave roughly 4.8 MiB of a 32 MiB GBA ROM for extra scene assets and growth. This is a budget, not a guarantee for arbitrary film length/complexity.

## Format
Same full-resolution 240x135 native picture region, palette and 30-Hz sampled picture timeline (60-Hz story/input clock). Little-endian u32 header: ROT3 magic 0x33544f52, sample count, last authored tick, seek count, total bytes. Then count+1 sequential record byte offsets (last is end of the sequential stream); then seek-count pairs of ascending sample index and byte offset, with recovery payloads following the sequential stream. At most 64 seek points. Each record has u16 decoded packet size and u16 LZ4 block size (zero for raw), with four-byte padding. Packet spans are u32 header (low16 absolute word offset, high16 positive word count) plus that many u32 pixels. Initial sequential sample and recovery records patch the immutable base; all subsequent sequential samples patch the preceding picture without resetting the base. No color or spatial resampling. Final odd logical tick is explicitly retained.

## Runtime and reuse
One shared 32 KiB packet workspace and leased game canvas. On a large/backward seek or scene reentry, recover from a nearby independent packet and apply at most two sequential deltas, otherwise seed once from the authored live painter. The Potheads encoder includes dialogue cues and selected extra anchors; other clips supply their own sorted list. The build compares every encoded record with the exact source raster and verifies the **production** cache decoder on sequential playback, cue jumps, random seeks and overwritten-canvas reentry. It refuses incorrect palette/raster data, out-of-bounds records or oversized clips. The live painter remains available (make clean && make OPENING_CACHE=0); generated cache and owner-private source inputs are not committed. Host gcc and liblz4-dev are required for cached builds.
