# ROT1 — compact native GBA film format
## Budget for a 21-scene game
The prior 1,274-tick Potheads cache occupied 11,004,712 bytes and brought the ROM to 13,061,684 bytes. A local C sanitizer-backed test on the extracted original ROM frames encoded 638 sampled pictures in 1,093,756 bytes including directory/padding (before optional raw-packet savings). All sampled 240x135 palette-index rasters compared byte-for-byte. The new CI generator enforces 1,258,291 bytes (approximately 1.2 MiB) per scene. Twenty-one scenes at that maximum plus the current approximately 2 MiB non-cache game consume approximately 27.2 MiB of the GBA's 32 MiB ROM address space, leaving approximately 4.8 MiB. Future content must be measured; this is a budget, not a guarantee for arbitrary long films. Shared live backgrounds and authored renderers may add their own ROM cost.
## Quality and timing
The output uses exactly the original indexed pixels at 30-Hz samples (even logical ticks and the true final pose). The game clock, music, cues and input remain at the original 60-Hz logical timing. Odd visual ticks hold the immediately preceding sample, at most one video interval. No palette reduction, spatial downsampling or invented intermediate frames. Full-resolution live rendering remains available using OPENING_CACHE=0. Raw reference media and private matte files are not added to the public repository.
## Format
Little-endian u32 header: ROT1 magic 0x31544f52, sample count, last logical tick, recovery interval (32 samples), total size in bytes. Then count+1 u32 byte offsets; last is end of clip. Each record starts with u16 decoded patch byte count and u16 LZ4 block byte count (zero means raw). Padding to 4-byte boundaries is not decoded. Patch commands are unsigned LEB128 skip (relative to end of prior write), unsigned LEB128 positive length, then exact palette bytes. A recovery record patches the clip's immutable base; other records patch the preceding sampled picture. All offsets, packet bounds and decoder writes are checked. Generator validates exact output and buffer guards for every sample.
## Reuse and seeking
One shared 38,400-byte picture and 32,768-byte packet workspace serves all future scenes. The generic decoder accepts the clip data, immutable base painter and authored live painter; independent scene identity and sample index prevent stale state. Normal rendering advances at most two samples per draw. A large jump, backward seek or scene switch seeds once from the original painter (or an independent recovery record), rather than replaying up to 31 frames. Captions are always drawn live after picture DMA. The host encoder uses liblz4 HC; the cartridge uses the small bounded decoder, not liblz4. Install host gcc and liblz4-dev to build; make clean && make OPENING_CACHE=0 selects the original painter. Actual mGBA cadence and memory budgets gate release.
